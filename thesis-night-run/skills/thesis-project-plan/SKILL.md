# 学位论文任务总规划

## 这个技能解决什么

把“要做什么”从散落的停点、任务书和决策记录里整理成一张可执行的网络：哪些是阶段，哪些是任务，谁做，依赖谁，哪条是关键路径，哪些要作者在场，哪些可以夜间跑。

它不替作者做学术决定，也不写正文。它只维护计划本身。

## 一、先读什么

- `06_讨论与确认/当前状态.md`
- `06_讨论与确认/决策记录.md` 末尾与相关 D 号
- 对应章节的 `任务书_*.md`
- `06_讨论与确认/README_索引.md`
- 当前构建路径与正式交付路径

没有当前状态，不要排计划。不要从记忆里的旧 D 号推断当前稿。

## 二、计划的最小结构

### 阶段

每个阶段写四件事：目标、入口条件、退出条件、交付物。阶段之间是依赖关系，不是日期。

### 任务

固定表头：

| ID | 任务 | 阶段 | 输入 | 输出 | 验收标准 | 依赖 | 负责人 | 模式 | Gate | 预估 |
|---|---|---|---|---|---|---|---|---|---|---|

字段说明：

- **负责人**：`作者` / `agent` / `共同`。
- **模式**：`attended`（必须作者在场）/ `T1`（可自动）/ `T2`（可自动但需复核）。
- **Gate**：任务依赖某个决定时填 `D-xxx`；没有填 `—`。未确认的决定不能写成普通任务。
- **验收标准**：必须是可检查的文件、表、命令输出或对照结果；不写“读起来顺不顺”。
- **预估**：只在有依据时填；没有就写 `—`，不要编造日期或工时。

### 关键路径

从当前停点到最终交付的最长依赖链。标出哪一项延期会让整条链后移。关键路径只标一条。

### 并行轨道

互不依赖、可同时推进的任务；与关键路径分开列，并写清汇合点。

### 风险与未决决策

| 风险或未决 | 影响 | 触发条件 | 处理 | 负责人 | 截止 |
|---|---|---|---|---|---|

## 三、与现有技能的分工

- `thesis-plan-grill`：决定“写什么、按什么顺序、哪些不写”，产出 D 号决策。
- 本技能：把已确认的决定拆成任务网络，标出依赖、关键路径、模式和 gate。
- `task-triage-night-run`：把可执行任务排成夜间清单，按 T1/T2/Gated 分级。

不要把三者混成一个：决策不是任务，任务不是夜间清单。

## 四、两种模式

### plan

输入：当前状态 + 决策记录 + 任务书。

输出：`06_讨论与确认/任务总规划_YYYYMMDD.md`，并在 `当前状态.md` 增加一行指针。

### track

输入：现有计划 + 最新停点。

输出：更新同一份计划，不新建；重算关键路径；标出完成、延期、阻塞；给下一批建议。

## 五、排计划的原则

1. 先阶段，后任务；先依赖，后并行；最后才谈预估。
2. 决策任务不放进可执行队列；它们进 `thesis-plan-grill`，产出 D 号后再变成任务。
3. 每个任务必须有验收标准；没有验收标准的任务不排。
4. 任务粒度以“一次可验收的交付物”为准；不要拆成“写一段”这种不可验收的单位。
5. 关键路径只标一条；并行轨道可以多条，但要有汇合点。
6. 预估只给区间或顺序，不编造具体日期；作者的时间容量由作者提供。
7. 计划是活文件；每次停点更新同一份，不复制多份“最新”。

## 六、计划头

```text
# 任务总规划
更新：YYYY-MM-DD
当前停点：...
最终交付：...
关键路径：T-... → T-... → T-...
并行轨道：...
```

## 七、一个最小例子

以 v2_1 摘要与第一章为例：

**阶段 A 材料提取**（入口：v2_1 批注版；出口：逐条意见清单）

- T-A1 提取批注与高亮，逐条编号（agent，T1）
- T-A2 对照导师摘要，列段落职责（agent，T1）

**阶段 B 结构诊断**（入口：意见清单；出口：主旨表与差异表）

- T-B1 现版摘要压成主旨表（agent，T1）
- T-B2 第一章 1.1～1.3 压成主旨表（agent，T1）
- T-B3 反推导师摘要的逻辑链（agent，T1）

**阶段 C 候选改写**（入口：作者确认诊断；出口：候选稿）

- T-C1 摘要候选（agent，T2；gate：本轮摘要决定）
- T-C2 第一章候选（agent，T2；gate：本轮结构决定）
- T-C3 术语与范围核对（agent，T1；gate：D-164、D-50 是否沿用）

**阶段 D 作者确认**（attended）

- T-D1 逐条确认候选（作者）
- T-D2 更新决策记录与任务书（agent，attended）

**阶段 E 构建与复核**（入口：确认稿；出口：PDF 与核查报告）

- T-E1 编译（agent，T1）
- T-E2 机器核查（agent，T1）
- T-E3 独立复核（agent，T1/T2）
- T-E4 替换 08（gate：作者明确“进 08”）

关键路径：T-A1 → T-B1/B2 → T-C1/C2 → T-D1 → T-E1 → T-E4。

这个例子只示结构；实际计划按当天停点生成，不要照抄任务。

## 八、边界

- 不替作者决定学术内容；只排任务。
- 不写正文、不改 07/08、不改任务书、术语表、决策记录。
- 不把“计划里列了”当成“已确认”。
- 不编造日期、工时、依赖；没有依据就写“待作者提供”。
- 计划更新后，在 `当前状态.md` 加一行指针；不要另起多份“最新”。
